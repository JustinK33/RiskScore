# Pinned dependency closure for the container image, and for nothing else.
#
# `pyproject.toml` keeps floors (`fastapi>=0.115`) because a library that pins
# exact versions is a library nobody can install alongside anything. An image is
# the opposite problem: two builds of the same commit that install different
# versions are two different artifacts with one tag, and the difference only
# shows up in production.
#
# So the Dockerfile installs this file first and then the project with
# `--no-deps`. Nothing in CI, the test suite, or a local `pip install -e .`
# reads it.
#
# Regenerate after changing the `[serve]` extra:
#
#     python3 -m venv /tmp/lockenv
#     /tmp/lockenv/bin/pip install ".[serve]"
#     /tmp/lockenv/bin/pip freeze | grep -v credit-default-risk-score | sort -f
#
# ponytail: versions only, no hashes. `--require-hashes` is the real supply-chain
# answer and needs pip-tools or `uv` to generate; add it when this image is
# published somewhere that matters rather than built from source by whoever runs
# it. Version pins already close the "two builds, two artifacts" gap, which is
# the one that bites during a demo.
#
# Not here, deliberately: xgboost, matplotlib, pyarrow. Those are the `[train]`
# extra and the image only serves - see the note in the Dockerfile about what
# that costs.
